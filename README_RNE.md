# MPC_G_MS：多智能体博弈 IGO 求解器

> **MPC_G_MS** = MPC with Game-theoretic Multi-agent IGO Solver
>
> 一句话概括：**多个智能体各自控制一部分决策变量，在不知道彼此策略的情况下，通过"我动、你不动"的反复试探，最终共同收敛到随机纳什均衡（RNE）。**

## 1. 从单目标优化到多智能体博弈

[基础 MGIGO](./README_IGO.md) 解决的是**单人优化**问题：有一个目标函数 $f(\mathbf{x})$，找一个最优的 $\mathbf{x}^*$。

`MPC_G_MS` 将这个问题扩展到**多智能体博弈**场景：

- 有 $M$ 个**独立决策的智能体**（agent），每个智能体有自己的代价函数
- 决策变量 $\mathbf{x}$ 被**划分**给各个智能体——智能体 $i$ 只能控制属于自己的那部分变量
- 每个智能体的代价**不仅取决于自己的决策，还取决于其他智能体的决策**
- 目标：找到**随机纳什均衡（RNE）**——在均衡点，任何智能体单方面改变自己的随机策略（搜索分布）都不会降低自己的期望代价

```
智能体 A 控制块 0,1          智能体 B 控制块 2
┌─────────────────┐         ┌─────────────┐
│  μ₀, S₀, π₀     │         │  μ₂, S₂, π₂ │
│  μ₁, S₁, π₁     │         │             │
└────────┬────────┘         └──────┬──────┘
         │                         │
         └─────────┬───────────────┘
                   ▼
         完整决策向量 x = [x₀ | x₁ | x₂]
                   │
                   ▼
    每个智能体用自己的代价函数评估
     f_A(x) ← 只看 A 关心的指标
     f_B(x) ← 只看 B 关心的指标
```

这与基础 MGIGO 的关系，就像**博弈论**与**最优化**的关系——从"一个人找最优"变成了"多个人在互相影响下各自找最优"。

## 2. 核心概念：异构块分配

### 块到智能体的映射

系统中总共有 $N_{\text{blocks}}$ 个决策块，但只有 $M_{\text{agent}}$ 个智能体。通过一个映射数组 `block_to_agent_idx` 指定每个块属于哪个智能体：

```
示例: N_blocks = 4, M_agent = 2
block_to_agent_idx = [0, 0, 1, 1]

Block 0 ──→ Agent 0
Block 1 ──→ Agent 0   (Agent 0 控制前两个块)
Block 2 ──→ Agent 1
Block 3 ──→ Agent 1   (Agent 1 控制后两个块)
```

这被称为**异构（heterogeneous）分配**，因为：
- 不同智能体可以控制不同数量的块
- 不同块可以有不同的维度
- 每个智能体有自己的代价函数 $f_{\text{agent\_i}}$

### 为什么需要这种设计？

在实际应用中很自然——例如**多机器人编队**：
- 机器人 A 控制自己的轨迹参数（几个块）
- 机器人 B 控制自己的轨迹参数（另外几个块）
- 每个机器人只关心自己是否到达目标，同时要避免碰撞
- 碰撞避免意味着代价函数包含了其他机器人的决策变量

## 3. 算法流程

### 总体框架

```
┌─────────────────────────────────────────────────────┐
│  输入: M个智能体的代价函数 f₁...f_M                   │
│        块的智能体归属映射 block_to_agent_idx          │
│        迭代次数 T, 样本数 B, 背景样本数 M_inner        │
└──────────────────────┬──────────────────────────────┘
                       ▼
              ┌────────────────┐
              │  t = 0...T-1   │  ← 迭代循环
              └───────┬────────┘
                      ▼
     ┌────────────────────────────────────────┐
     │  步骤1: 所有块并行采样                   │
     │  - 候选池: 每块采 B 个候选动作           │
     │  - 背景池: 每块采 M_inner 个背景动作     │
     └────────────────┬───────────────────────┘
                      ▼
     ┌────────────────────────────────────────┐
     │  步骤2: 对每个智能体，评估其候选动作      │
     │  - "我"的块用候选池的第 b 个动作         │
     │  - "别人"的块用背景池的随机快照          │
     │  - 对 M_inner 个背景快照取期望           │
     │  → 得到每个候选动作的期望代价            │
     └────────────────┬───────────────────────┘
                      ▼
     ┌────────────────────────────────────────┐
     │  步骤3: 每个智能体独立排序，分配精英权重  │
     │  - 代价低的候选获得高权重               │
     │  - 权重通过映射表广播到各块             │
     └────────────────┬───────────────────────┘
                      ▼
     ┌────────────────────────────────────────┐
     │  步骤4: 每块独立进行自然梯度更新          │
     │  - 周期性重置权重                       │
     └────────────────┬───────────────────────┘
                      ▼
              是否达到 T 次？
                 /        \
               是          否 → 回到步骤1
                ↓
┌─────────────────────────────────────────────────────┐
│  输出: 所有块的均值 μ、Cholesky L、混合权重 π       │
│        每个智能体的聚合策略                         │
└─────────────────────────────────────────────────────┘
```

### 与基础 MGIGO 的核心差异

| 方面 | 基础 MGIGO | MPC_G_MS |
|------|-----------|----------|
| 评估方式 | 直接计算 $f(\mathbf{x})$ | 对智能体 $i$ 计算 $\mathbb{E}_{\text{others}}[f_i(\mathbf{x})]$ |
| 精英筛选 | 全局排序一次 | 每个智能体**各自独立排序** |
| 权重来源 | 全局精英权重 | 按智能体归属**映射**到各块 |

## 4. 关键创新：期望代价评估

这是 MPC_G_MS 最核心的设计。当智能体 $i$ 评估自己的候选动作时，它**不知道其他智能体会采取什么动作**。解决方案是：用其他智能体当前搜索分布的**随机样本**来近似"别人会做什么"。

### 双池采样

每轮迭代生成两个样本池：

| 样本池 | 大小 | 用途 |
|--------|------|------|
| 候选池 `samples_B` | $B$ | 当前智能体自己的候选动作 |
| 背景池 `samples_M` | $M_{\text{inner}}$ | 其他智能体的"背景行为"快照 |

### 期望代价计算

```
对智能体 i 的第 b 个候选动作：

  joint₁ = [候选动作_b (我的块) | 背景快照₁ (别人的块)]  →  f_i(joint₁)
  joint₂ = [候选动作_b (我的块) | 背景快照₂ (别人的块)]  →  f_i(joint₂)
  ...
  joint_M = [候选动作_b (我的块) | 背景快照_M (别人的块)]  →  f_i(joint_M)

  期望代价 = mean(f_i(joint₁), ..., f_i(joint_M))
```

用代码来说（`_step_fn_rne_blocks` 第 114-139 行）：

```python
def evaluate_agent_expected_cost(agent_idx):
    block_mask = (block_to_agent_idx == agent_idx)  # 哪些块是我的

    for b in range(B):  # 对每个候选动作
        for m in range(M_inner):  # 对每个背景快照
            joint = samples_M[:, m, :]              # 默认全用背景池
            joint[my_blocks] = samples_B[my_blocks, b, :]  # 我的块替换为候选
            cost = fitness_fn(agent_idx, joint)      # 评估联合代价

        expected_cost[b] = mean(cost over all m)    # 对背景取平均
```

### 直觉

这类似于**虚构博弈（fictitious play）**的思想：
- 每个智能体假设其他智能体会按照它们当前的搜索分布来行动
- 对自己的候选动作，通过蒙特卡洛采样来**边际化**掉对其他智能体的不确定性
- 随着迭代进行，所有智能体的搜索分布逐步收敛，期望评估也越来越准确

## 5. 随机纳什均衡（RNE）

RNE = **Randomized Nash Equilibrium**，即**随机纳什均衡**。

### 确定性策略 vs 随机化策略

在经典博弈论中，**纯策略（pure strategy）**指智能体每次选一个确定的动作。**混合策略（mixed strategy）**则指智能体按概率分布随机选动作——这在博弈中有重要意义（例如石头剪刀布中，任何纯策略都会被对手利用，只有随机化策略才能避免被 exploit）。

MPC_G_MS 中的每个智能体维护的不是一个确定的决策值，而是一个**高斯混合分布**——这就是随机化策略：

$$q_i(\mathbf{x}_i) = \sum_{k=1}^{K} \pi_k \cdot \mathcal{N}(\mathbf{x}_i | \boldsymbol{\mu}_k, \mathbf{S}_k^{-1})$$

### 随机纳什均衡的定义

一组概率分布 $(q_1^*, q_2^*, \ldots, q_M^*)$ 构成**随机纳什均衡**，当且仅当对于每个智能体 $i$：

$$q_i^* = \arg\min_{q_i} \mathbb{E}_{\mathbf{x}_i \sim q_i,\; \mathbf{x}_{-i} \sim q_{-i}^*}\left[f_i(\mathbf{x}_i, \mathbf{x}_{-i})\right]$$

即：**当其他智能体的随机策略固定时，智能体 $i$ 找不到另一个分布 $q_i$ 能进一步降低自己的期望代价。**

### 算法如何逼近 RNE

每轮迭代等价于对所有智能体同步执行一步**迭代最佳响应（iterative best response）**：

1. 固定其他智能体的搜索分布 $q_{-i}$（用背景池样本近似）
2. 在当前 $q_i$ 下采样候选动作，用背景池蒙特卡洛估计期望代价 $\hat{f}_i$
3. 沿自然梯度方向将 $q_i$ 向代价更低的方向移动 $\alpha$ 步
4. 所有智能体同步完成更新

### 基线分量的作用

$K$ 个高斯分量中的最后一个被用作**基线（baseline）**。在混合权重更新中：

$$v_k \leftarrow v_k + \alpha \cdot \sum_i w_i \cdot (a_i - b_i)$$

- $a_i$：分量 $k$ 对样本的解释力（后验责任）
- $b_i$：基线分量对样本的解释力
- 差值 $a_i - b_i$：**分量 $k$ 相对于基线的"超额解释力"**

**直觉**：一个分量只有表现得比基线更好，才值得被保留。基线作为"锚点"防止搜索分布坍缩到单一模态，维持了算法的**随机化**特性——这也是它能收敛到随机纳什均衡（而非确定性最优点）的关键。

## 6. 与基础 MGIGO 的关系

MPC_G_MS 可以看作是基础 MGIGO 在**博弈方向**的扩展：

| | 基础 MGIGO | MPC_G_MS |
|---|---|---|
| 智能体数 | 1 | $M \geq 1$ |
| 代价函数 | 全局 $f(\mathbf{x})$ | 每个智能体 $f_i(\mathbf{x})$ |
| 策略类型 | 随机化搜索分布 | 随机化搜索分布（**随机纳什均衡**） |
| 评估 | 一次函数调用 | $B \times M_{\text{inner}}$ 次（蒙特卡洛期望） |
| 精英选择 | 全局 top-B₀ | 每个智能体独立 top-B₀ |
| 权重广播 | 直接使用 | 通过 `block_to_agent_idx` 映射 |
| 权重更新 | $a_{k,b} - a_{K,b}$（相对第K分量） | $a_{k,b} - b_{k,b}$（相对基线分量） |

### 当 M=1 时

当只有一个智能体（$M=1$，所有块都属于它）时，MPC_G_MS 退化为带基线正则化的 MGIGO。此时：
- `block_to_agent_idx = [0, 0, ..., 0]`
- 背景池采样仍然存在，但因为所有块都属于同一个智能体，候选动作会同时替换所有块
- 期望评估退化为对自身采样噪声的平均（仍有一定平滑效果）

## 7. 参数速查

基础 MGIGO 的[参数表](../README_IGO.md#6-关键参数速查)仍然适用，以下是 MPC_G_MS 新增的参数：

| 参数 | 符号 | 含义 |
|------|------|------|
| 智能体数 | $M_{\text{agent}}$ | 独立博弈的智能体数量 |
| 总块数 | $N_{\text{blocks}}$ | 所有智能体的块数总和 |
| 块归属映射 | `block_to_agent_idx` | 长度 $N_{\text{blocks}}$，值为 $0 \ldots M_{\text{agent}}-1$ |
| 背景样本数 | $M_{\text{inner}}$ | 用于估计期望代价的背景快照数。越大估计越准，但计算量线性增长 |
| 智能体代价函数 | `fitness_fn_j` | 签名为 `(agent_idx, joint_x, context) -> scalar` |

## 8. 代码结构

```
igo/
├── blockwise_mgigo_jax.py   ← 基础 MGIGO 求解器
├── MPC_G_MS.py              ← 本文件：多智能体博弈扩展
├── utils.py
└── plot_utils.py
```

### 核心函数调用关系

```
mmog_igo_rne_blocks_solver()           ← 顶层入口
  └── lax.scan(
        _step_fn_rne_blocks()           ← 每轮迭代
          ├── v_to_pi()                 ← 自然参数 → 单纯形权重
          ├── sample_all_blocks()       ← 双池采样（候选 B + 背景 M_inner）
          ├── evaluate_agent_expected_cost()  ← ★ 博弈核心
          │     └── fitness_fn_j()      ← 智能体代价函数
          ├── 精英排序 & 权重广播        ← 按 block_to_agent_idx 映射
          └── update_single_block()     ← 每块独立更新
                └── _update_block_component_core()  ← ★ 随机纳什均衡更新
                      ├── 责任 a_i（分量 k 对样本的解释力）
                      ├── 责任 b_i（基线分量对样本的解释力）
                      ├── 精度更新（使用 a_i）
                      ├── 均值更新（使用 a_i）
                      └── 权重增量 ∝ (a_i - b_i)  ← 相对基线的优势
      )
```

### 技术要点

- **全 JAX 实现**：继承基础 MGIGO 的 `lax.scan` + `vmap` 架构
- **SPD 投影**：`_safe_spd_projection()` 通过特征值裁剪保证精度矩阵始终正定
- **双池采样**：候选池和背景池共享同一分布，但使用不同的随机种子独立生成
- **联合快照构造**：使用 `jnp.where(block_mask, candidate, background)` 高效切换
- **智能体并行评估**：`vmap(evaluate_agent_expected_cost)` 并行评估所有智能体
